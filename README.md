# Melog

> 떠오른 멜로디를 기록하고 보관하는 iOS 앱

**Melog(멜로그)**는 `Melody + Log`의 합성어입니다. 사용자가 허밍이나 단선율 멜로디를 빠르게 녹음하고, 실시간 파형을 확인하며, 녹음 기록을 폴더와 즐겨찾기로 정리할 수 있도록 만드는 프로젝트입니다.

현재 MVP를 개발 중이며 로그인 없이 기기 내부에서 사용할 수 있는 구조를 우선합니다.

## 주요 기능
- 마이크 권한 요청
- 멜로디 녹음 시작, 종료, 취소
- 녹음 중 경과 시간 표시
- 실시간 음량 파형 표시
- 녹음 파일을 기기 내부에 저장
- SwiftData를 이용한 녹음 메타데이터 저장
- 보관함과 사용자 폴더 UI
- 개인정보 처리방침 및 서비스 이용약관 화면
- 한국어 및 영어 앱 이름 지원
- 앱 실행 시 랜덤 인트로 문구 표시
- 녹음 기록 재생 및 편집
- 즐겨찾기와 태그 기반 스마트 컬렉션
- 실시간 음정 및 음 이름 표시
- 녹음 종료 후 BPM, Key, 리듬 분석
- 단선율 악보 변환
- 녹음 검색 및 데이터 내보내기
- 멜로디 지도 기능

## 기술 스택

| 구분 | 기술 |
| --- | --- |
| UI | SwiftUI |
| 상태 관리 | Observation (`@Observable`) |
| 데이터 저장 | SwiftData |
| 오디오 | AVFoundation, AVAudioRecorder |
| 비동기 처리 | Swift Concurrency, async/await |
| 로컬라이징 | String Catalog, InfoPlist.strings |
| 지원 플랫폼 | iOS |

## 프로젝트 구조

```text
Melog
├── App
│   └── MelogApp.swift
├── Root
│   └── RootView.swift
├── Features
│   ├── Home
│   ├── Recording
│   ├── FolderDetail
│   ├── MainTab
│   ├── Map
│   └── Settings
├── Models
├── Services
│   └── Recording
├── Shared
│   └── Components
└── Resources
    ├── Assets.xcassets
    ├── Localizable.xcstrings
    └── DesignSystem.swift
```

- `Features`: 화면 단위 기능과 ViewModel
- `Models`: 앱에서 사용하는 데이터 모델
- `Services`: 녹음, 파일 저장 등 외부 시스템과 연결되는 기능
- `Shared`: 여러 Feature에서 공통으로 사용하는 View와 코드
- `Resources`: 이미지, 색상, 문자열과 디자인 리소스

## 실행 방법

### 요구 사항

- macOS
- 최신 안정 버전 Xcode
- 마이크를 사용할 수 있는 iPhone 권장

### 실행

1. 저장소를 Clone합니다.
2. `Melog.xcodeproj`를 Xcode에서 엽니다.
3. Signing & Capabilities에서 본인의 Development Team을 선택합니다.
4. 실행할 iPhone 또는 Simulator를 선택합니다.
5. `Command + R`로 실행합니다.
6. 녹음 기능을 처음 사용할 때 마이크 접근을 허용합니다.

오디오 입력과 권한 동작은 Simulator보다 실제 iPhone에서 테스트하는 것을 권장합니다.

## Git 협업 규칙

### 브랜치 전략

| 브랜치 | 역할 |
| --- | --- |
| `main` | 배포 가능한 안정 버전 |
| `dev` | 다음 배포를 위한 통합 브랜치 |
| `feat/이슈번호-기능명` | 새로운 기능 개발 |
| `fix/이슈번호-문제명` | 버그 수정 |
| `refactor/이슈번호-대상명` | 동작 변경 없는 구조 개선 |
| `docs/이슈번호-문서명` | README 및 문서 수정 |
| `chore/이슈번호-작업명` | 설정, 빌드 및 기타 작업 |

모든 작업 브랜치에는 연결된 GitHub Issue 번호를 포함합니다. 브랜치 이름은 영문 소문자, 숫자, 하이픈을 사용합니다.

```text
feat/12-audio-recording
feat/18-favorites
fix/23-record-button
refactor/31-recording-service
```

`#` 문자는 터미널에서 주석으로 처리될 수 있으므로 브랜치 이름에는 숫자만 작성합니다. PR과 커밋 메시지에서 이슈를 언급할 때는 `#12` 형식을 사용합니다.

### 작업 흐름

1. 작업 내용을 설명하는 GitHub Issue를 먼저 생성합니다.
2. 작업 전 `dev`를 최신 상태로 동기화합니다.
3. `dev`에서 이슈 번호가 포함된 작업 브랜치를 생성합니다.
4. 하나의 목적에 집중해 작업하고 의미 단위로 커밋합니다.
5. 작업 브랜치를 원격 저장소에 Push합니다.
6. 작업 브랜치에서 `dev`를 대상으로 Pull Request를 생성합니다.
7. PR 본문에 `Close #이슈번호`를 작성해 관련 이슈를 연결합니다.
8. 리뷰와 수정이 끝나면 `dev`에 병합합니다.
9. 배포 준비가 완료되면 `dev`에서 `main`으로 Pull Request를 생성합니다.

`main`과 `dev`에는 직접 Push하지 않는 것을 원칙으로 합니다.

## 커밋 메시지 규칙

다음 형식을 사용합니다.

```text
type: 작업 내용
```

| Type | 설명 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변화 없는 구조 개선 |
| `design` | UI 및 디자인 변경 |
| `docs` | 문서 작성 및 수정 |
| `test` | 테스트 추가 및 수정 |
| `chore` | 설정, 의존성 및 기타 작업 |
| `remove` | 파일이나 코드 제거 |

예시:

```text
feat: 실시간 녹음 파형 표시
fix: 녹음 종료 후 타이머 초기화
refactor: 녹음 파일 경로 관리 분리
design: 보관함 폴더 카드 스타일 수정
docs: README 협업 규칙 추가
```

### 커밋 원칙

- 커밋 하나에는 하나의 목적만 담습니다.
- 파일 개수가 아니라 의미 있는 작업 단위로 커밋합니다.
- `수정`, `작업`, `최종`처럼 내용을 알 수 없는 메시지는 사용하지 않습니다.
- 빌드되지 않는 상태를 가능한 한 공유 브랜치에 Push하지 않습니다.
- API 키, 인증 정보, 개인 설정 파일은 커밋하지 않습니다.

## Pull Request 규칙

### PR 제목

커밋 메시지와 같은 형식을 권장합니다.

```text
feat: 녹음 및 실시간 파형 기능 구현
```

### PR 본문에 포함할 내용

```markdown
## 작업 내용
- 구현하거나 변경한 내용을 작성합니다.

## 확인 방법
- 리뷰어가 기능을 확인하는 방법을 작성합니다.

## 스크린샷
- UI 변경이 있다면 전후 화면을 첨부합니다.

## 관련 이슈
- Close #이슈번호
```

### PR 체크리스트

- [ ] 프로젝트가 정상적으로 빌드되는가?
- [ ] 요구한 기능이 정상적으로 동작하는가?
- [ ] 불필요한 디버그 코드와 주석을 제거했는가?
- [ ] UI 변경을 실제 기기 또는 Preview에서 확인했는가?
- [ ] 마이크 권한 거부와 오류 상태를 확인했는가?
- [ ] 민감한 정보가 포함되지 않았는가?
- [ ] 새로운 파일이 적절한 폴더에 위치하는가?

### 리뷰 규칙

- 코드가 아니라 문제와 개선 방향을 중심으로 의견을 작성합니다.
- 수정이 필요한 의견은 이유와 대안을 함께 남깁니다.
- 반영이 끝난 리뷰 대화는 확인 후 Resolve합니다.
- 작성자는 모든 리뷰 의견을 확인한 뒤 병합합니다.

## Issue 규칙

이슈 제목에도 작업 유형을 표시합니다.

```text
[Feat] 녹음 재생 기능
[Fix] 마이크 권한 거부 시 버튼 반응 없음
[Design] 설정 화면 카드 UI 개선
```

이슈에는 작업 배경, 완료 조건, 참고 자료를 작성합니다.

## 개인정보 및 데이터

- Melog는 현재 회원가입과 로그인을 사용하지 않습니다.
- 녹음 파일과 메타데이터는 기기 내부에 저장됩니다.
- 현재 버전은 녹음 파일을 외부 서버로 전송하지 않습니다.
- 마이크는 사용자가 녹음을 실행한 동안에만 사용합니다.

기능 또는 데이터 처리 방식이 변경되면 앱 내 개인정보 처리방침과 이 문서를 함께 갱신해야 합니다.
